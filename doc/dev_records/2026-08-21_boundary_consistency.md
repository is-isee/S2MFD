# 境界条件の整合性 — 保存テストでは捕まらない誤り (2026-08-21)

**保存則が machine precision で成り立っていても、境界条件が正しいとは
限らない。**このプロジェクトで実際に 2 か月近く見落としていた誤りと、
それを検出する手法を記録する。

---

## 1. なぜ保存テストで捕まらないのか

保存形の更新は

```
dq[i] = -(F[i+1] - F[i])/drr[i]
```

で、体積積分は `sum(q*drr)` なので telescoping して `F_N - F_0` になる。
S2MFD は境界面のフラックスを **リテラルの 0.0 で上書き**している:

```python
# conservative.zero_boundary_faces_r
for j in range(jxg):
    ff[margin, j] = 0.0
    ff[ixg - margin, j] = 0.0
```

したがって **両端が厳密にゼロである限り、ゴーストセルに何が入っていても
総和は変わらない**。保存は境界条件ではなく「フラックスを潰すこと」で
担保されている。

### 検出手法: ゴーストを壊してみる

> **ゴーストセルを毎ステップ物理的にありえない乱数で潰し、それでも
> 保存量が machine precision で保たれるかを見る。**
> 保たれるなら、その保存テストは境界条件を一切検証していない。

実測 (48x48、200 ステップ):

| 設定 | dM/M | dL/L |
|---|---|---|
| 通常 | 3.70e-20 | -1.11e-19 |
| **ゴーストを毎ステップ 1e4 の乱数で破壊** | **2.48e-20** | **-9.13e-20** |

まったく変わらない。`tests/test_conservation.py` の
`test_conservation_does_not_depend_on_ghost_cells` で固定した。

---

## 2. では境界条件はどう検証するか

### 検出手法: 「潰す前」の面フラックスを測る

ゴーストから面平均で作った境界面のフラックスを、`zero_boundary_faces`
で 0.0 にする**前**に見る。整合した境界条件なら、それ自体が機械精度で
ゼロになるはずである。

実測 (上部境界、規格化):

| 境界条件 | 質量流束 | 角運動量流束 |
|---|---|---|
| **旧: `v_r` を反対称** | **-1.00e-01** | -9.50e-02 |
| **新: `rho_0 r^2 v_r` を反対称** | **-5.6e-17** | +6.77e-03 |

旧実装では境界面の質量流束が **10% 残っていて、それを 0 で潰していた**。

---

## 3. 正しい形

保存量は `q_mr = r^2 sin(theta) rho_0 v_r` なので、境界を横切る質量流束を
ゼロにするなら **速度ではなく質量流束を反対称**にするのが正しい:

```
v[m-1] = -v[m] * (rho_0[m] r[m]^2) / (rho_0[m-1] r[m-1]^2)
```

`JV = r^2 sin(theta) rho_0` だから

```
JV[m-1] v[m-1] = -r[m]^2 sin(theta) rho_0[m] v[m] = -JV[m] v[m]
```

となり面平均が厳密にゼロ。`cfg.mass_flux_bc` (既定 True) で切り替える。
`v_theta` で `v_theta/r` を対称にしているのと同じ発想。

### 角運動量はどうやっても合わない

角運動量流束は `JL (Omega_0 + Omega_1) v_r`、`JL = rho_0 r^4 sin^3(theta)`。
質量は `r^2`、角運動量は `r^4` の重みなので、**`v_r` のゴースト 1 つで
両方をゼロにはできない**。新 BC でも 6.8e-03 残る (旧 BC の 9.5e-02 より
1 桁以上マシではある)。

保存は zero_boundary_faces が担保するので実害はないが、
**「境界のゴーストは常にどこかで不整合」**という前提で考えるべき。

---

## 4. 不整合はどこに効くか

ゴーストは境界面フラックス以外でも使われる:

* 最内・最外セルの中心差分 (圧力勾配、ローレンツ力、粘性の源項)
* SLD の再構成の傾き (境界 2 セル分)

旧 BC ではそこに 10% の不整合が入り、しかも **`rho_0` の変化が最も急な
上部境界に集中する**。

実測されている症状 (`2026-08-21_nonuniform_grid.md` 参照):

* `v_r` の 2 セル振動が境界に向かって単調に増え、最外セルで滑らかな
  成分の **1.8 倍**に達する
* **解像度を上げても改善しない** (108 で 1.84、144 で 1.88)
* 4 次ハイパー拡散も効かない (境界面フラックスを 0 にするので届かない)
* 格子を伸縮させても 1.5-1.65 までしか下がらない

「解像度にも人工拡散にも依存しない」という性質は、離散化の粗さでは
なく**境界条件の不整合**が原因であることを強く示唆する。

---

## 5. 一般化できる教訓

1. **保存テストが通ることは、境界条件の正しさを何も保証しない。**
   フラックスをゼロで潰す実装では特にそうである。
2. **ゴーストを壊して保存を測る**と、そのテストが何を検証しているかが
   分かる。変わらなければ境界条件は検証されていない。
3. **「潰す前」の面フラックスを直接測る**のが境界条件の整合性テスト。
4. 保存量が複数ある場合 (質量 `r^2`、角運動量 `r^4`)、**1 つのゴースト値で
   全部を整合させることはできない**。どれを優先するかは設計判断になる。
5. 「解像度を上げても改善しない」症状は、離散化誤差ではなく
   **境界条件・定式化の誤り**を疑う合図。
