# 動径方向の非一様格子 (2026-08-21)

差動回転の解像度依存性の **84% が動径方向**、しかも対流層/放射層境界の
薄い層 (`d_bc = 0.05 R_sun`、領域深さの 16%) が効いていることが
分かった (`2026-08-20_resolution_and_numerical_viscosity.md`)。
一様格子でそこを解像しようとすると全域が高コストになるので、
**その場所に点を集められる**ようにした。

`cfg.grid_stretch > 0` で有効。既定は 0 (一様) で、既存の結果とは
**ビット単位で一致**する。

---

## 1. 何を実装したか

### 座標

有限体積なので **面 (セル境界) が主**で、セル中心は面の中点にする。

| 配列 | 定義 | 用途 |
|---|---|---|
| `grid.rrm[i]` | 面 (セル `i-1` と `i` の境界) | 面上の量 |
| `grid.rr[i]` | `0.5*(rrm[i] + rrm[i+1])` | セル中心 |
| `grid.drr[i]` | `rrm[i+1] - rrm[i]` (**セル幅**) | 発散・体積積分 |
| `grid.drrm[i]` | `rr[i] - rr[i-1]` (**中心間距離**) | 面での勾配 |
| `grid.drr2[i]` | `rr[i+1] - rr[i-1]` | セル中心の 2 セル中心差分 |
| `grid.wfm[i]` | 面への線形補間の重み | 面平均 |

**この 3 つ (`drr` / `drrm` / `drr2`) を取り違えるのが一番の事故のもと。**
一様格子では `drr == drrm == drr2/2` なので取り違えてもテストが通って
しまう。非一様格子のテストを入れてあるのはこのため。

### 保存が壊れない理由

発散を `dq[i] -= (F[i+1]-F[i])/drr[i]`、体積積分を `sum(q*drr[i])*dth`
にすると

```
sum_i dq[i]*drr[i] = -sum_i (F[i+1]-F[i]) = -(F[N] - F[0])
```

と telescoping がそのまま成立する。**面値をどう補間しても成り立つ**ので、
補間の選択は精度だけの問題。逆に `cell_integral` を「一様格子だから」と
スカラーに戻すと即座に壊れる (テストで固定した)。

### 伸縮写像

点の密度をガウシアンの和で与え、その積分を誤差関数で**解析的に**書く:

```
rho(r) = 1 + sum_i a_i exp(-((r - r_i)/w_i)^2)
k(r)   = C [ (r - rmin)
             + sum_i a_i w_i (sqrt(pi)/2)
               (erf((r-r_i)/w_i) - erf((rmin-r_i)/w_i)) ]
```

`k(rmin) = 0`, `k(rmax) = ix` になるよう `C` を決め、面の位置は
`k(r) = k_face` を **Newton 法**で解いて求める (`k' = C*rho` も解析的)。
機械精度まで収束するので、**格子生成に補間を一切使わない**。

`stretch` / `stretch_center` / `stretch_width` は配列でもよく、
複数箇所 (タコクラインと表面) に同時に集中できる。
`stretch_width = 0` は自動 (領域幅の 15%)。

## 2. 測って初めて分かったこと

### (a) 格子生成器の滑らかさが離散化の次数を決める

最初は「密度を数値積分してテーブルを作り `np.interp` で逆に引く」
方式にしていた。区分線形補間なので**格子間隔関数が C^0 にしかならず、
その折れ目が 1 次の誤差を注入して全体が 1 次精度に落ちた**。

`scratchpad/order_test.py` (テーブル方式) の実測:

| ix | 面の単純平均 | 次数 | 距離重み付き | 次数 | 中心差分 | 次数 |
|---|---|---|---|---|---|---|
| 108 | 6.02e-03 | 1.03 | 1.71e-03 | 2.00 | 2.83e-03 | 1.94 |
| 432 | 1.71e-03 | 0.94 | 1.07e-04 | 2.00 | 1.80e-04 | 1.99 |
| 864 | 8.76e-04 | 0.97 | 2.68e-05 | 2.00 | 4.50e-05 | 2.00 |

`scratchpad/order2.py` (解析的な写像) に変えると:

| ix | 単純平均 | 次数 | 重み付き | 次数 | 拡散 | 次数 | **解の誤差** | 次数 |
|---|---|---|---|---|---|---|---|---|
| 108 | 1.71e-03 | 1.93 | 1.62e-03 | 1.96 | 6.41e-04 | 2.00 | 3.75e-04 | 2.10 |
| 1728 | 6.98e-06 | 2.00 | 6.52e-06 | 2.00 | 2.50e-06 | 2.00 | 1.37e-06 | 2.01 |

> **教訓**: 非一様格子で 2 次精度が保たれるかは「伸縮の強さ」ではなく
> **「写像が滑らかかどうか」**で決まる。格子生成器に補間を使うと、
> どんなに細かいテーブルでも折れ目が効いて次数が落ちる。

### (b) 面値の単純平均は落ちうる

セル中心が面の中点でないので `0.5*(q[i-1]+q[i])` は面の値ではない。
滑らかな写像なら実用上 2 次を保つ (上表) が、距離重み付き線形補間なら
**写像の滑らかさに依らず厳密に 2 次**になる。コストはゼロで、保存性は
どんな補間でも成り立つので、保険として採用した。

### (c) SLD の再構成は「単位長さあたりの傾き」でなければならない

minmod に生の差分を渡すと、**線形な場でもセル幅の違いだけでリミタが
発動**して滑らかな解を削る。`(q[i]-q[i-1])/drrm[i]` を傾きにし、
セル幅 `drr` を掛けて面へ外挿する形に直した。
一様格子では `drr == drrm` なので従来と代数的に同一。

### (d) 全体の収束次数を測るときは境界セルを外す

`rhs` 全体を汎関数 (滑らかな重みとの内積) で測ると、**境界セルを含めると
一様格子でも 1 次**になる。境界処理由来で伸縮とは無関係。端で高次に
ゼロになる窓を掛けると一様 2.00 / 伸縮 2.00 になる。

内挿を挟むと内挿誤差が同じ次数で混ざって測定が濁るので、
**格子ごとの求積で汎関数を評価して比較**する。

## 3. 検証結果

| 項目 | 結果 |
|---|---|
| `stretch=0` で `rr`/`drr`/`drrm`/`drr2`/`wfm` が旧実装とビット一致 | ✓ |
| 伸縮格子の角運動量保存 `dL/L` | 1.6e-20 |
| 伸縮格子の質量保存 `dM/M` | 8.9e-21 |
| `rhs` 全体の収束次数 (一様) | 2.00 |
| `rhs` 全体の収束次数 (伸縮 b=2.5) | 2.00 |
| 線形な場に人工拡散が乗らない (伸縮格子) | ✓ |
| テスト | 157 件通過 |

一様格子のビット一致を守るため、`stretch == 0` のときは面の差分では
なく**旧式をそのまま使う分岐**を残してある。ここを「整理」して消すと
回帰テストのゴールデン値が動く。

## 4. 効果

### 差動回転の収束

t=3 yr での DR:

| 格子 | DR | 相対コスト |
|---|---|---|
| 108x144 一様 | 0.2896 | 1.0 |
| 144x192 一様 | 0.2857 | 2.4 |
| **108x144 伸縮 (b=2.5)** | **0.2869** | **1.5** |

伸縮 108x144 が 144x192 一様にほぼ並ぶ。**約 1.6 倍お得**。
(dt が 156 -> 103 s に落ちるのが伸縮のコスト。)

### 上部境界の格子スケール振動

`v_r` は上部境界に向かって 2 セル振動を増幅させる。
`scratchpad/topcheck.py` で測った「格子スケール成分 / 振幅」(上位 10%):

| ラン | 比 | 最大位置 |
|---|---|---|
| 0.960R 一様 108 | 1.84 | 0.9557R (最外セル) |
| 0.960R 一様 **144** | **1.88** | 0.9568R |
| 0.985R 一様 108 | 1.49 | 0.9803R |
| **0.985R 伸縮 108** | **0.46** | 0.9780R |

**比が 1 を超える = 滑らかな成分より 2 セル振動のほうが大きい。**
しかも一様格子では 144x192 に上げても改善しない (1.84 -> 1.88)。
セル幅を局所の `H_p` に合わせる伸縮格子だけが効く (1/3〜1/4)。
中間領域 (0.7-0.85R) では比が 0.01 まで下がる。

`v_theta`, `Omega_1`, `s_1` は上部境界まできれいで、格子スケール成分は
1% 以下。`rho_1` は 5% 程度 (音波の残差)。

## 5. 上部境界を 0.985 R_sun へ

`rrmax = 0.96 R_sun` にしていた理由 (uniform 格子では 0.985 で発散した)
は `parameters/rempel06.py` に書いてある。現行コードで測り直すと
**0.985 R_sun は一様格子でも通る** (t=0.9 yr まで収支残差 4.5e-16)。
以前の発散はその後の修正 (`-F.grad u` の散逸加熱、SLD の特性速度、
磁場の境界条件) で解消していたと思われる。

0.985 にする積極的な理由が 2 つある:

1. **alpha 層の位置**。論文の
   `f_alpha(r) = max[0, 1 - (r-rmax)^2/d_alpha^2]` は alpha 層を
   **上部境界に張り付ける**定義で、論文では 0.935-0.985 R_sun。
   `rrmax = 0.96` だと 0.91-0.96 と **0.025 R_sun 深い位置**にずれる。
   B_r が論文比 -31%、周期が -8% ずれているのはこれが原因の可能性が高い。
2. **表面の子午面流**。`v_theta` が 0.970R で 8.62 m/s、
   **0.985R で 9.77 m/s** と論文の ~10 m/s に近づく。

| 上部境界 | rho 比 (底/上) | H_p | Delta r/H_p (108 点) | dt |
|---|---|---|---|---|
| 0.960 R_sun | 40 | 11732 km | 0.170 | 490 s |
| 0.980 | 102 | 6567 | 0.324 | 563 |
| 0.985 | 145 | 5241 | **0.412** | 547 |

**dt はむしろ増える** (音速も落ちるため)。効くのは `Delta r/H_p` だけ。
タコクライン (0.715R) と表面 (0.985R) の 2 点集中で
`Delta r/H_p` が 0.412 -> **0.18** (0.96R 一様の 0.170 と同等) になる。
